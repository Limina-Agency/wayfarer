# Releasing

Two release lines: `wayfarer-v<version>` (package, costing, engine, service, C
ABI) and `wayfarer-compiler-v<version>` (the `wayfarer` binary and the compiler
crates). A change to
the costing model releases both.

1. **Decide what changed.**
   - Package layout: bump `ROUTING_PACKAGE_FORMAT_VERSION`, keep reading the
     previous format, and add `fixtures/routing/format-<N>/` with a package of
     the new format. A released format's fixture is frozen: never regenerate
     it. Raising `MIN_READ_FORMAT_VERSION` drops a format: delete its fixture
     and say so in the changelog. Today both are 2 (`fixtures/routing/format-2/`).
   - Stored costs: bump `COSTING_MODEL_VERSION` and release both lines.
   - C ABI: an incompatible change to `wayfarer.h` bumps
     `WAYFARER_ABI_VERSION`.
2. **Run the gates** on a quiet machine (no other builds or simulators):
   `scripts/check.sh`, then `benchmarks/gates/gates.sh` on the
   Małopolskie extract against the previous release. Packages must be
   byte-identical unless the release changes the format or the costing; dumps
   must be identical unless the release changes results on purpose; timings
   within 3%.
3. **Bump versions** in the workspace `Cargo.toml` and the path dependencies'
   `version`, then update `CHANGELOG.md`: what changed, formats read and
   written, costing model, ABI version.
4. **Tag** `wayfarer-v<version>` and/or `wayfarer-compiler-v<version>` and push the
   tag. The release workflow builds the `wayfarer` binaries (archives
   `wayfarer-<version>-<target>`) and the C libraries with the header and
   attaches them to the GitHub release, with the package hash of the Monaco
   fixture each `wayfarer` binary writes, for Linux (x86_64,
   aarch64), Windows and macOS (Apple silicon). There are no Intel macOS
   archives: build from source or `cargo install`.
5. **Publish** the crates to crates.io in dependency order:
   `wayfarer-package`, `wayfarer-costing`,
   `wayfarer-road-graph`, `wayfarer`, `wayfarer-service`, `wayfarer-sar`
   (none needs the compiler), then
   `wayfarer-line-network`, `wayfarer-compiler`, `wayfarer-cli` and
   `wayfarer-ffi` (its optional `compiler` feature needs the compiler
   on crates.io). The PBF reader, `osm-pbf-ingest`, is released from its own
   repository.
6. **Third-party notices.** The release workflow puts a
   `THIRD_PARTY_LICENSES.txt` in each archive, generated by `cargo about`
   (`about.toml`, `about.hbs`) from the crates that archive links. A new
   dependency under a license `about.toml` doesn't accept fails the release:
   review it and add the license. Every build today links only Apache-2.0,
   MIT, zlib and Unicode-3.0 crates.
